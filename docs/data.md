# Data

This document describes every data source the product reads, how it is
retrieved, its schema, and the analysis performed on it. The goal is that an
external analyst can reproduce the results without access to anything except
this repository and public endpoints.

## Sources

### 1. Nibiru oracle precompile (on-chain, primary)

The price under measurement. Read directly from the Nibiru EVM through a
precompiled oracle contract via standard JSON-RPC `eth_call`.

- Transport: `POST {NIBIRU_RPC_URL}` (`eth_call`)
- Contract: `0x000000000000000000000000000000000000000000000801` (same address on Testnet-2 and mainnet)
- Method: `queryExchangeRate(string pair)` — 4-byte selector `0x6bd1902f`
- Returns: `(uint256 exchangeRate, uint64 updateBlockTimestampMs, uint64 updateBlockHeight)`
- Units: `exchangeRate` is the price of one `base` denom expressed in the
  `quote` denom, at 18 fixed-point decimals. Pairs use oracle-module format
  (`base:quote`), for example `ueth:uusd` = ETH priced in `uusd`.

No API key and no account are required to read the oracle; it is public chain
state. The reader lives in `src/oracle/precompile.ts`. Reads are anchored to the
`latest` block, and the block the oracle last updated (`updateBlockHeight`) plus
its timestamp (`updateBlockTimestampMs`) are captured so staleness is measured
against real chain time.

### 2. Independent reference prices (off-chain)

To judge whether an oracle rate is correct, it is compared with a price
produced outside Nibiru. References come from public exchange endpoints, tried
in a configurable order so one provider's outage or rate limit does not blind
the monitor. Providers are implemented in `src/oracle/reference.ts`:

| Provider    | Endpoint                                       | Auth            | Quote |
| ----------- | ---------------------------------------------- | --------------- | ----- |
| `coinbase`  | `api.coinbase.com/v2/prices/{SYM}-USD/spot`    | none            | USD   |
| `kraken`    | `api.kraken.com/0/public/Ticker?pair=`         | none            | USD   |
| `binance`   | `data-api.binance.vision/api/v3/ticker/price`  | none            | USDT  |
| `coingecko` | `api.coingecko.com/api/v3/simple/price`        | optional demo key | USD |

- First provider that quotes a symbol wins; the rest are recorded as fallbacks.
- `binance` is USDT-quoted, so it is ordered last and flagged in the quote
  metadata (`note: "USDT-quoted (not USD)"`). Because the quote stablecoin is
  itself oracle-priced, a Binance-sourced reference is not fully independent of
  the oracle at the USD layer.
- `coingecko` frequently rate-limits (HTTP 403) without a demo key; every symbol
  is still covered by the exchange providers, so this is non-fatal.
- Each quote records its provenance: provider, retrieval time (`retrievedAt`),
  the provider's own last-trade time (`upstreamLastUpdate`), and any note.

Symbol mapping is configured with `REFERENCE_SYMBOLS` (e.g.
`ueth=ETH,ubtc=BTC,uusdc=USDC,unibi=NIBI`). A base denom with no mapping is
monitored for freshness only and reported as `unavailable` for deviation.

## Schema

Storage is append-only JSON Lines — one `Snapshot` object per line in
`data/state.jsonl` (gitignored; regenerated by the monitor). A committed copy
of the full demonstration dataset lives in `data/samples/example-snapshots.jsonl`.

```jsonc
{
  "network": "Nibiru Testnet-2",
  "chainId": 6911,
  "block": 9704107,              // EVM block oracle reads anchored to
  "collectedAt": "2026-09-29T16:22:45.772Z",
  "samples": [
    {
      "pair": "ueth:uusd",
      "chainId": 6911,
      "oracleRate": 2681.16,     // rate in quote-denom per base-denom (float)
      "referenceUsd": 2679.705,  // independent reference, USD (null if none)
      "deviationBps": 5.4,       // signed deviation, basis points (null if no ref)
      "oracleAgeSeconds": 9,     // now - oracle updateBlockTimestampMs
      "status": "ok",            // ok | warning | critical | stale | unavailable
      "reason": "...",           // human-readable classification
      "oracleUpdateBlockHeight": 9704107,
      "oracleUpdateBlockTimestampMs": 1789000000000,
      "oracleBlock": 9704107,
      "reference": { "source": "coinbase", "retrievedAt": "...", "upstreamLastUpdate": "..." }
    }
  ],
  "notes": []                    // non-fatal collection problems (e.g. provider outage)
}
```

Bigint fields are serialized as decimal strings when written.

## Cleaning and transformations

The pipeline performs only deterministic, lossless transforms; nothing is
invented or imputed:

1. **Oracle rate decoding.** The raw `uint256` is divided by 1e18 to a plain
   decimal rate.
2. **Age.** `oracleAgeSeconds = now - oracleUpdateBlockTimestampMs/1000`.
3. **Reference selection.** Providers are attempted in configured order; the
   first numeric quote > 0 for a symbol is kept, with full provenance.
4. **Denomination alignment.** Both sides are normalized to like-for-like units
   before comparison, so deviation is measured between prices in the same terms.
5. **Deviation.** `deviationBps = 10000 * (oracle - reference) / reference`,
   signed. When no reference is available the field is `null` and the sample is
   reported on freshness alone.

No sample is dropped silently: if an oracle read reverts (for example the
`uusd:uusd` base pair, which the oracle module rejects as an unsupported legacy
symbol), the pair is kept with `status = "unavailable"` and the reason recorded
in `notes`.

## Analytical methodology

Integrity classification (`src/analysis/integrity.ts`) uses fixed thresholds
from configuration:

- **Staleness:** `oracleAgeSeconds > MAX_ORACLE_AGE_SECONDS` (default 60s).
- **Deviation:** `|deviationBps| >= DEVIATION_WARN_BPS` (default 50) → warning;
  `>= DEVIATION_CRITICAL_BPS` (default 200) → critical.
- Precedence: a price breach outranks staleness; staleness outranks a plain
  "ok". A sample with no reference is judged on freshness alone.

Aggregate statistics (`summarize`) are population statistics over the absolute
deviations of samples that had a reference: mean, population standard deviation,
maximum, and a breach count. These are recomputed on demand from the JSONL
store; they are not stored as fixed numbers.

## Observed results (this dataset)

Reproduce with `node scripts/stats.cjs` (it reads the committed file and
prints everything below). Over the committed window:

- 204 snapshots, 816 pair-samples (204 each for `unibi/ueth/ubtc/uusdc`).
- 614 of 816 samples had an independent reference. NIBI is mapped to a
  reference symbol, but free endpoints list it only sporadically: Coinbase
  answered 3 times in this window, so the other `unibi:uusd` samples are
  freshness-only and say so in their status reason.
- Absolute deviation vs reference: **mean 4.00 bps, median 3.90 bps, population
  stdev 1.49 bps, max 20.13 bps** — well inside the 50 bps warning threshold. No
  critical or stale samples occurred during the window.

These numbers describe one observation window on a testnet and are the input to
the dashboard and attestation flow, not a general claim about oracle behavior.

## Limitations

- Reference providers are centralized exchanges with their own maintenance and
  rate-limit behavior; an outage reduces coverage but never fabricates a value.
- Binance references are USDT-denominated and therefore not independent of the
  USD layer at the margin.
- NIBI has no keyless reference mapping in the default config, so its samples
  report freshness only unless a `REFERENCE_SYMBOLS` mapping is added.
- Testnet oracle values are mirrored by the chain and can lag; the monitor
  reports what the chain actually serves rather than what it "should" serve.
